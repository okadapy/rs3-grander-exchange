# Фронтенд RS3 Market — дизайн

Дата: 2026-09-15
Статус: согласован, готов к написанию плана

## 1. Задача

Веб-интерфейс к RS3 Market API: показать скиллы персонажа, дать таблицу
выгодности крафта и живой чат с обновлением цен. Тёмная тема, React,
TypeScript, типы генерируются из OpenAPI внешним инструментом.

## 2. Состояние бэкенда на момент дизайна

Бэкенд живёт в отдельном репозитории `/home/okada/code/rs3-actioneer`,
поднят через docker compose, гейтвей слушает `http://localhost:8080`.
Фронтенд — отдельный репозиторий `/home/okada/code/rs3-market`.

Проверено запросами: развёрнутая версия соответствует `combined.yaml`
v2.0.0. Присутствуют и отвечают ожидаемыми формами `/health`,
`/health/all`, `/recipes`, `/recipes/ids`, `/recipes/{id}`,
`/recipes/{id}/tree`, `/search/recipes`, `/search/items`,
`/items/limits`, `/prices/latest`, `/prices/history/{id}`,
`/prices/change/{id}`, `/prices/stats/{id}`, `/calc/{id}`,
`/calc/batch`, `/hiscore/{name}`, `/auth/register`, `/auth/login`,
`/chat/history`, `/ws`.

### 2.1 Известный дефект данных (на стороне бэкенда)

У каждого снапшота цены `price = 0` при живом `volume`. До пересборки
те же строки отдавали `buy: 307, sell: 307` — миграция, схлопнувшая
`buy`/`sell` в `price`, значение не перенесла.

Следствия, которые фронтенд обязан переживать без падений:

- `/calc/{id}` и записи в `/calc/batch` отвечают
  `"no priceable production path for item N"` для любого предмета;
- в `/prices/stats/{id}` поля `price_min`, `price_max`, `price_avg`,
  `price_last`, `volatility_pct` нулевые, а `score` и `tier` при этом
  осмысленные, потому что считаются в основном по объёму.

Решение: строим фронтенд сейчас, автотесты идут на MSW-моках с
правдоподобными числами. Пустой результат расчёта показывается честно
(«сервер не смог оценить»), а не как нулевая маржа. Когда цены
наполнятся, таблица прогоняется на живых данных.

### 2.2 Свойства данных, влияющие на дизайн

- 8311 рецептов всего; `/recipes` не пагинируется и отдаёт 4.1 МБ.
  Полный список никогда не грузим.
- Фильтр `skill` на `/recipes` и `/recipes/ids` регистронезависим:
  `crafting`, `Crafting` и `CRAFTING` дают одинаковые 1041 и 739.
  Грязный регистр в базе клиентского обхода не требует.
- В поле `skill` встречаются значения `No`, `no`, `None` (925 записей)
  — это не скиллы. В выборе скилла их нет.
- У части рецептов `output_item_id = 0` — выходной предмет не
  сопоставлен, оценить нельзя. `/recipes/ids` такие уже исключает:
  для Crafting 1041 рецепт, но 739 оцениваемых id.
- Гейтвей отдаёт ответы без gzip. `/recipes?skill=Smithing` — 737 КБ
  на один запрос. Это стоит включить на бэкенде; фронтенд компенсирует
  тем, что держит такой ответ в кэше и запрашивает раз на скилл.
- `/hiscore/{name}` возвращает 30 записей: `Overall` плюс 29 скиллов.

## 4. Генерация типов

`npm run gen:api` запускает `openapi-typescript ../combined.yaml -o
src/api/schema.d.ts`. Результат коммитится, чтобы сборка не зависела
ни от живого бэкенда, ни от сети.

`src/api/client.ts` создаёт `createClient<paths>({ baseUrl })`, где
`baseUrl` берётся из `VITE_API_URL` (по умолчанию
`http://localhost:8080`). Никакой доменный код не обращается к
`fetch` напрямую и не объявляет собственных интерфейсов ответа —
единственный источник форм это `schema.d.ts`.

WebSocket генератором не покрывается (это не HTTP), но типы кадров
`WsCommand`, `WsEnvelope`, `PriceSnapshot`, `ChatMessage` в схеме есть
и переиспользуются как есть.

## 5. Структура

```
src/
  api/          schema.d.ts, client.ts, queries/ (по тегу API)
  ws/           соединение, реконнект, роутинг кадров по типу
  theme/        палитра, типографика, оверрайды MUI
  assets/       иконки скиллов (скачаны), резолвер иконок предметов
  features/
    character/  страница персонажа
    recipes/    таблица, фильтры, сборка строки
    chat/       чат, формы входа и регистрации
  shared/       форматирование чисел, чипы, состояния загрузки и ошибок
```

Правило границ: `features/*` не знают об `openapi-fetch` и обращаются
только к хукам из `api/queries`. Сборка строки таблицы — чистая
функция, принимающая четыре ответа и отдающая модель строки; она
тестируется без React.

## 6. Единый экран

Отдельных страниц и маршрутов больше нет. Весь интерфейс — один экран из
трёх зон, чтобы не переключаться между персонажем и расчётом крафта.

```
┌──────────────────────────────────────────────┐
│ RS3 Market                                 ● │  шапка + индикатор
├───────────────┬──────────────────────────────┤
│ персонаж      │ рецепты                      │
│ (левая        │ (центральная зона,           │
│  колонка,     │  занимает всю оставшуюся     │
│  прокрутка)   │  ширину)                     │
│               │                              │
│               │            ┌───────────────┐ │
│               │            │ чат (попап)   │ │
└───────────────┴────────────┴───────────────┴─┘
```

**Язык интерфейса — английский.** Весь текст, который видит пользователь:
подписи, кнопки, заголовки колонок, сообщения об ошибках и пустых
состояниях. Русский остаётся только в проектной документации и в
сообщениях коммитов.

Левая колонка имеет фиксированную ширину и собственную прокрутку.
Центральная зона забирает всё остальное. Чат — попап в правом нижнем углу:
свёрнутый занимает узкую плашку, развёрнутый всплывает поверх содержимого.
Ни одна зона не наезжает на другую и не отнимает ширину у таблицы.

### Индикатор состояния сервисов

Текста в шапке нет — только цветная точка с доступной подписью:

| Цвет | Значение | Источник |
|---|---|---|
| зелёный | все сервисы в строю | `all_upstreams_ok: true` |
| жёлтый | часть сервисов не отвечает | `all_upstreams_ok: false`, но гейтвей ответил |
| красный | сервисы недоступны | запрос к `/health/all` не прошёл |

## 7. Персонаж (левая колонка)

Ввод имени и режима (`normal`, `ironman`, `hardcore`, параметр
`HiscoreMode`) → `GET /hiscore/{name}`.

Сверху — ник и **суммарный уровень рядом с ним, в одной строке**, из записи
`Overall`.

Время получения данных остаётся, но подписью мелким приглушённым шрифтом,
чтобы не мозолило глаз. Убрать его совсем нельзя: бэкенд молча отдаёт
устаревшую копию, когда хайскоры недоступны, и `fetched_at` — единственный
признак, по которому это отличимо.

Ниже — вертикальная колонка из 29 строк со своей прокруткой: иконка скилла,
название, уровень, опыт, ранг и полоса прогресса опыта до следующего уровня.
Внутри строки всё выстроено в одну горизонтальную линию. Порядок — как
приходит из API.

Таблицы опыта выверены по вики: обычная кривая (уровень 99 — 13 034 431,
110 — 38 737 661, 120 — 104 273 167) и отдельная elite-кривая для Invention,
единственного elite-скилла в игре (99 — 36 073 511, 120 — 80 618 654).
Archaeology, Dungeoneering и Necromancy elite не являются.

Потолок уровня не задаётся жёстко: хайскоры отдают виртуальные уровни выше
99 — живой ответ показывает Attack уровня 120 у игрока с 200 000 000 опыта.
Обе таблицы доведены до уровня 150. Жёсткий потолок опыта — 200 000 000 на
скилл; на нём полоса полная, а вместо процента пишется, что достигнут
максимум.

У `Overall` полосы нет: это сумма уровней, а не уровень на кривой.

Клик по строке скилла фильтрует таблицу рецептов по этому скиллу. Строка —
настоящая кнопка, достижимая с клавиатуры. `Overall` не кликабелен.

Имя и режим сохраняются в localStorage и уходят в `player=` и `mode=` при
расчёте: тогда `/calc` возвращает `skill_requirements` и
`meets_requirements`, и недоступные персонажу строки гасятся.

## 8. Рецепты (центральная зона)

### 8.1 Поток данных

**Когда скилл не выбран, таблица показывает все крафты**, а не пустое
состояние. Фильтр по скиллу сужает выборку, а не включает её.

1. Костяк строк: `GET /recipes` без фильтра, либо `GET /recipes?skill=X`
   при выбранном скилле. Кэш на час. Строки с `output_item_id = 0`
   отбрасываются — их нельзя оценить.
2. `GET /recipes/ids` (с теми же фильтрами или без них) — множество
   оцениваемых id; пересекается с костяком.
3. Пагинация по 25 строк на клиенте. Для текущей страницы:
   `GET /calc/batch`, `GET /prices/latest`, и `GET /prices/stats/{id}`
   на строку.
4. Из ответов собирается модель строки; из `CalcResult.paths` берётся
   первый путь — бэкенд ранжирует их лучшим первым.

Ограничение, которое надо снять новой спекой: `/recipes` без фильтра
отдаёт 8311 рецептов одним куском на 4.1 МБ без gzip. Для «всех крафтов»
нужен пагинируемый источник костяка либо сжатие на гейтвее.

### 8.2 Колонки

| Колонка | Источник |
|---|---|
| Skill | иконка по `Recipe.skill` |
| Item | иконка по `output_item_id` + `output_item_name` |
| Level | `level_req`, с отметкой по `meets_requirements` |
| Price | `PriceSnapshot.price` |
| Components | `CalcPath.buy_cost` |
| Margin | `CalcPath.profit_per_craft` |
| ROI | `CalcPath.roi_pct` |
| XP/h | `CalcPath.xp_per_hour` |
| GP/h | `CalcPath.gp_per_hour` |
| GP/XP | `CalcPath.gp_per_xp` |
| GP/h (limit) | `CalcThroughput.gp_per_hour` |
| Liquidity | `LiquidityStats.tier`, `score`, `observations`, `volume_avg` |

`GP/XP` показывает, во что обходится опыт: при обучении скилла отрицательное
значение — это цена уровня, а не убыток.

Сортировка и фильтрация — средствами DataGrid, в пределах загруженной
страницы. Ограничение подписано в интерфейсе.

### 8.3 Оговорки, без которых числа врут

- `complete: false` — какой-то вход не удалось оценить, он посчитан по нулю,
  маржа является верхней границей. Строка помечается, числа приглушаются,
  в подсказке перечисляются `unpriced_inputs`.
- `aph_source: "default"` — скорость действий принята сервером, а не
  измерена. Помечается на колонках XP/h, GP/h и GP/XP.
- `throughput` — четырёхчасовой лимит GE на связывающий вход и GP/ч, который
  этот лимит реально позволяет. Часто на порядок ниже `gp_per_hour`, поэтому
  стоит отдельной колонкой.

Блок `CalcResult.assumptions` показывается над таблицей: GP/ч без допущений,
на которых он посчитан, смысла не имеет.

Ошибка по записи `CalcBatchEntry.error` не роняет страницу: строка остаётся,
причина указывается один раз, денежные колонки показывают прочерк.

## 9. Чат (попап)

Попап в правом нижнем углу, не отдельная страница и не маршрут. Свёрнутый —
узкая плашка с признаком непрочитанного. Развёрнутый — панель поверх
содержимого, не отнимающая ширину у таблицы.

`GET /chat/history?limit=50` даёт историю, `before` — курсор для подгрузки
вверх. Живые сообщения приходят кадрами `type: "chat"`.

Регистрация `POST /auth/register`, вход `POST /auth/login`. JWT в
localStorage. Отказ токена показывается явно, с кнопкой выйти.

Отправка идёт кадром `{action: "chat", body}`, а не HTTP. Своё сообщение
отображается, только когда вернулось эхом от сервера — это гарантирует
единый порядок у всех клиентов.

## 10. Живые обновления цен

Один сокет на приложение. При смене страницы таблицы он шлёт `subscribe` с
id текущей страницы и `unsubscribe` при уходе. Кадр `type: "price"` патчит
кэш TanStack Query и коротко подсвечивает строку.

Сокет требует JWT, поэтому без входа живых цен нет. Деградация:
неавторизованный пользователь получает опрос `/prices/latest` раз в 30
секунд. Расчётные колонки по кадру цены не пересчитываются: маржа считается
на сервере, и подменять её клиентской арифметикой значит расходиться с
`/calc`. Строка помечается устаревшей, с кнопкой пересчёта.

Реконнект с экспоненциальной задержкой и восстановлением подписок. Кадры
`heartbeat` держат соединение, `error` показывается пользователю.

## 11. Тема и ассеты

Тёмная тема MUI: глубокий нейтральный фон, две ступени поверхностей для
карточек и строк таблицы, золотой акцент как отсылка к RS без стилизации под
игру. Зелёный и красный только для знака прибыли, с дополнительным
различием по знаку числа. Плотная типографика с табличными цифрами.

Эмодзи не используются нигде.

- Иконки скиллов: `https://runescape.wiki/images/{Skill}-icon.png`, все 29
  проверены. Скачиваются скриптом в `public/icons/skills/`, коммитятся, в
  рантайме внешних запросов нет. `Overall` иконки не имеет.
- Иконки предметов:
  `https://secure.runescape.com/m=itemdb_rs/obj_big.gif?id={itemID}`,
  грузятся по требованию, при ошибке — нейтральная заглушка.

## 12. Ошибки

Три разных состояния, которые нельзя смешивать в одно «ошибка»:

- сеть или гейтвей недоступны — предложение повторить;
- `502 upstream unavailable` от гейтвея (наблюдалось, пока
  recipe-service поднимался) — сообщаем, какой сервис лежит, из поля
  `target`, и повторяем автоматически;
- доменный отказ (`404 no recipe`, `no priceable production path`) —
  это не поломка, а ответ. Показывается текстом в месте данных.

`/health/all` опрашивается раз в минуту и питает индикатор в шапке,
чтобы «пусто» и «бэкенд лежит» различались с одного взгляда.

## 13. Тестирование

Vitest, Testing Library, MSW. Моки строятся из сгенерированных типов,
поэтому расхождение со схемой ломает компиляцию тестов, а не прод.

Покрываем:

- сборку строки таблицы из четырёх ответов, включая частичные:
  нет цены, нет статистики, `CalcBatchEntry.error`;
- отображение оговорок: `complete: false` приглушает числа и
  показывает `unpriced_inputs`; `aph_source: "default"` помечает
  XP/ч и GP/ч; `throughput` ниже `gp_per_hour` видна отдельно;
- форматирование денег, опыта и процентов, включая отрицательную
  маржу и очень большие числа;
- страницу персонажа: успех, 404, устаревший `fetched_at`;
- вход, регистрацию, протухший токен;
- редьюсер кадров WS: чат, цена, heartbeat, error, реконнект с
  восстановлением подписок.

Полный прогон выполняется один раз по завершении задачи, внутри
контейнера.

  Tailwind с рукописными типами формы v1 (`PriceSnapshot` как
